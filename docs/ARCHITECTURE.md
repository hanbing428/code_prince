# 架构与接口约定

## 当前技术和分层

沿用 HBuilderX uni-app、Vue 3、JavaScript、Options API 与 CSS/SCSS。无需第三方运行依赖。

`pages/` → `api/index.js` 业务方法 → `api/request.js` → 默认 `mock/handler.js`。`api/endpoints.js` 集中保存接口方法和候选 REST 地址；`config/index.js` 保存模拟开关与待填基地址。

页面只持有展示和交互状态。业务存储只在模拟处理器里访问，通过可注入的 storage 适配器进行单元测试；本地缓存版本变更需明确迁移或重置策略，不静默覆盖用户数据。

## 数据关系

- user：id、昵称、角色、账号状态。
- memorial：id、ownerId、名字、种类、日期、寄语、封面、可见性、留言开关、审核状态。
- memory、tribute、message：均关联 memorialId 和创建者；媒体路径由上传接口返回。
- report：举报者、对象类型/编号、原因、处理状态。
- 当前 session 与种子数据一起保存在模拟缓存，不包含真实身份凭据。

## 接口契约

业务方法均返回 Promise，成功结果为 `{ data }`，失败抛出带 `code` 的 Error（如 UNAUTHORIZED、FORBIDDEN、NOT_FOUND、VALIDATION_ERROR）。实际地址以 `api/endpoints.js` 为准，未来与后端协商后集中调整。

覆盖身份、个人资料、注销，馆列表/详情/增改删，回忆增删查，祭奠增查，留言增删查，举报，媒体上传，以及管理员举报、馆、留言、用户管理。

`useMock=true` 时绝不调用真实请求。关闭模拟后必须配置 HTTPS 基地址，真实 request 与 multipart 上传入口保留，但本次不配置、不调用、不宣称已联调。后端必须验证登录、资源归属、私密访问、管理员权限、输入和请求幂等，不能信任客户端字段。

更新接口使用 PUT，页面调用方法名称不依赖 HTTP 动词。用户资料更新只允许昵称，纪念馆更新只允许业务字段；ownerId、role、status 不从普通表单透传。真实登录凭证适配仍待后端阶段完成，不能只改开关就视为联调完毕。

## 当前决定

- DEC-001（已确认，2026-11-05）：个人纪念优先、免费、默认私密，沿用现有技术栈。
- DEC-002（已确认，2026-11-05）：不接真实后端，接口层与静态模拟同步实现。用户未来明确要求接后端时复审。
- DEC-003（实施选择）：采用现有 Options API 和少量公用样式、工具函数，避免为了首版引入库。
- DEC-004（实施选择）：项目内保留 Skill 源文件，安装副本用于发现；AGENTS 和文档是动态规则的唯一来源。
- DEC-005（实施选择）：页面临时展示名为“念念”，不是已确认的商标或正式品牌名。
