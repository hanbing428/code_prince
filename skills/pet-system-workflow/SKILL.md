# 宠物纪念项目工作流

本项目为已逝宠物保存回忆、提供云祭奠和亲友纪念，目标平台为微信小程序。当前采用 uni-app、Vue 3、JavaScript；不接真实后端，所有业务操作通过预留的接口层模拟。

## 定位与恢复

1. 从当前工作目录定位 `pet_system_uni` 项目根目录，先读其 `AGENTS.md`，以其中最新规则为准。不能定位时询问项目位置，不依赖固定盘符。
2. 读取 `docs/HANDOFF.md` 和 `docs/TRACEABILITY.md` 的相关条目，再按任务读取需求、架构、直接实现与测试，避免全仓无差别读取。
3. 区分已确认要求、候选建议和当前授权。用户只要求讨论时只给方案；授权开发后继续完成必要实现与验证，不重复询问已授权事项。

## 执行

- 说明本次可观察目标与重要假设，按任务大小使用简短步骤。需要改变产品范围的未知取舍再询问。
- 保持中文注释、中文沟通、自定义函数小驼峰以及项目现有格式。只做必要修改，不擅自迁移框架或新增库。
- 业务页面只调用 `api/`，接口契约集中维护。需要新能力时同时补充模拟实现；不得把静态数据直接塞进页面，也不得用接入真实服务替代用户要求的模拟实现。
- 修改前检查相关文件和未提交内容，保留用户工作。优先复用已有文档，不为局部改动生成整套重复档案。
- 对权限、重复提交、日期不详和失败反馈验证可观察行为。模拟身份与客户端权限仅用于演示，不能声称具备生产安全性。
- 更新受影响的需求、实现、测试和交接状态。交付说明入口、实际能力、已执行验证和待验事项。
- 微信开发者工具、真机、后端和发布各自记录验证状态，不把浏览器或单元测试通过等同于微信验收。

## 常见调用

- `$pet-system-workflow 继续当前项目进度。`
- `$pet-system-workflow 为纪念馆增加一个字段，先分析影响再实现。`
- `$pet-system-workflow 检查私密纪念馆访问与模拟接口行为。`

详细业务规则和用户偏好只在项目 `AGENTS.md` 与需求文档维护。安装副本不保存另一套动态进度。发布、真实接口接入与付费操作不因调用本 Skill 获得授权。
